# Specification: Acroname USB Hub

**Track ID:** acroname-hub_20261012
**Type:** Feature
**Created:** 2026-10-12
**Status:** Draft

## Summary

Add a `Hub` driver for the Acroname USBHub3p (`educelab.devices.hubs.acroname`) so consumers can power-cycle USB ports, typically to reset hung cameras.

## Context

On `pgs-scan` `dev`, `utils/usb_hub3p_config.py` and `utils/usb_hub3p_reset.py` drive the hub directly through `brainstem` (`setPortDisable`/`setPortEnable`, `setEnumerationDelay`). They are standalone scripts, not part of the app.

## User Story

As a rig operator or application developer, I want to power-cycle a specific USB port through the `Hub` interface so that a hung device can be recovered without unplugging it.

## Acceptance Criteria

- [x] `[acroname]` extra (`brainstem`); lazy import, so `brainstem`'s import-time `ImportError` on unrecognized Linux distros only affects this backend.
- [x] `AcronameHub` is a `Device` and `Hub`; `discover()` lists connected hubs by serial number.
- [x] Per-port power on/off/state and `power_cycle(port, off_seconds)`; brainstem error codes mapped to the `DeviceError` hierarchy with readable messages.
- [x] Enumeration delay exposed as a hub setting.
- [x] Tests on a fake brainstem layer; `Hub` contract suite passes.
- [x] `docs/hardware/acroname-usbhub3p.md` (udev rules, MSVC redistributable on Windows, Linux distro caveat).
- [x] `el-devices hub` subcommand: list hubs, show port state, power-cycle a port.
