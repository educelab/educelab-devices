# Specification: Camera Lens Information

**Track ID:** camera-lens-info_20261118
**Type:** Feature
**Created:** 2026-11-18
**Status:** Pending (stub)

## Summary

Let callers read the current focal length and lens information from a camera when the camera provides it, through one call on the generic `Camera` base that returns `None` when it doesn't. From issue #40.

This is a stub. The open questions below get settled, and the plan written, when the track starts.

## Problem Description

- No camera reports what lens is mounted or its focal length. Consumers that need it (e.g. for capture metadata) have no way to ask.
- Support varies: gphoto2 cameras with electronic lenses often report lens model and focal length; machine-vision bodies with manual lenses usually can't know what's mounted, though some GenICam cameras expose `Lens*`/`DeviceLens*` features.

## Open Questions

- Shape of the result: one small dataclass (e.g. `LensInfo` with optional `model`, `focal_length`, `focal_length_range`, `aperture`) or separate properties.
- Whether it's read live on each call, and whether it can change mid-session (zoom lenses, lens swaps).
- Whether it also belongs in per-frame or per-file metadata.

## Acceptance Criteria

- [ ] The `Camera` base has the public method and a driver hook that defaults to `None`.
- [ ] Drivers that can report lens information do: gphoto2 first, then GenICam bodies that expose lens features.
- [ ] `SimulatedCamera` can present lens information, or none, so consumers can test both paths.
- [ ] The camera contract suite covers it, `docs/guide.md` describes it, and `docs/hardware/` records what each lab camera actually reports.

## Dependencies

- Existing code: `cameras/base.py`, `cameras/gphoto2.py`, `cameras/_genicam.py`, `cameras/simulated.py`. Tests: `tests/contracts/`.
- Needs hardware checks on the lab's cameras; batch them at the end of the track.

## Out of Scope

- Controlling the lens (zoom, aperture as a lens setting); focus stays with the focus drive.
