# Specification: CLI Errors and Missing SDKs

**Track ID:** cli-missing-sdks_20261104
**Type:** Refactor
**Created:** 2026-11-04
**Status:** Pending

## Summary

A missing or broken vendor SDK becomes a `DeviceError` with a one-line message. `el-devices` handles it in one place, and `discover` stops printing a paragraph for every backend that isn't installed.

From the architecture review of 2026-11-04.

## Problem Description

- `errors.import_optional()` raises a plain `ImportError`, so `cli.main` (`app/cli.py:57-62`) doesn't catch it.
- Four subcommands catch it themselves (`app/hub.py:86-99`, `app/dslr.py:55`, `app/genicam.py:50`, `app/spinnaker.py:30`).
- The other four (misha, xlc, xcarve, foldio) don't, so a missing pyserial or bleak ends in a traceback, and no test covers it.
- The messages are too long to be useful. The Aravis and Spinnaker hints are whole install recipes inlined into the error.
- `discover` with nothing installed prints eight two-line blocks.
- A module that is installed but fails to import (e.g. a PySpin wheel built against the wrong numpy) gets the same "install it with…" advice as one that's absent.
- The `_level` argparse type is copied in `app/misha.py:39` and `app/xlc.py:34`, with a variant in `app/foldio.py:133`. The position formatter is copied in `app/xcarve.py:185` and `app/simulate.py:126`.

## Acceptance Criteria

- [ ] `import_optional()` raises `MissingDependency`, a subclass of both `DeviceError` and `ImportError`, only when the module asked for (or one of its parents) isn't installed.
- [ ] Any other import failure raises `DependencyFailed`, also both a `DeviceError` and an `ImportError`. Its message is the original error, in one line.
- [ ] Code that catches `ImportError` keeps working.
- [ ] A missing-SDK message is one line: the module, then either the single `pip install 'educelab-devices[extra]'` command or the full URL of a hardware-doc anchor. Install recipes live only in the hardware docs.
- [ ] `cli.main` maps `DeviceError` (now including missing SDKs) and Ctrl-C to exit codes. No subcommand catches `ImportError`.
- [ ] Each subcommand still turns its own bad-input `ValueError`/`KeyError` into an exit code, as hub and xcarve do today.
- [ ] One test covers a missing SDK for every subcommand.
- [ ] `el-devices discover` lists unavailable backends on one trailing line, `Not available: a, b, … (-v for why)`. `-v` prints each one's message.
- [ ] The shared argparse types and formatters live in `app/_args.py`.
- [ ] `docs/guide.md` §5 (Errors) describes the two new errors.

## Dependencies

- Existing code: `errors.py`, every `load_*`/`import_optional` call site (`cameras/aravis.py`, `cameras/spinnaker.py`, `cameras/_gphoto2.py`, `cameras/gentl.py`, `_serial.py`, `stages/foldio360.py`, `hubs/acroname.py`), `app/`.
- Docs: `docs/hardware/usb3-vision.md` and `docs/hardware/spinnaker.md` take the install recipes, under stable anchors.
- Runs after `genicam-deepening_20261104`.

## Out of Scope

- A catch-all in `cli.main`. It would hide real bugs.
- The GenTL "no producer found" message, beyond making it one line.
