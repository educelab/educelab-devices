# Specification: Documentation Site

**Track ID:** docs-site_20261012
**Type:** Chore
**Created:** 2026-10-12
**Status:** Draft

## Summary

Publish the project and hardware documentation as a MkDocs Material site on GitHub Pages, with an API reference generated from docstrings.

## Motivation

The hardware docs are meant to be the lab's reference for every device, and the guide and API reference are how new consumers learn the package. Markdown in the repo is hard to browse and search; a site makes it usable. The pattern follows `sample-mounts` (MkDocs Material → GitHub Pages).

## Success Criteria

- [ ] `mkdocs.yml` with Material theme and navigation: Home, Guide, Hardware (index + per-device docs), Decisions (ADRs), API reference.
- [ ] `docs/index.md` home page; README links to the published site.
- [ ] API reference generated with mkdocstrings (Google-style docstrings) for the public API.
- [ ] `docs` dependency group (`mkdocs-material`, `mkdocstrings[python]`, `mkdocs<2`); builds with pip, no uv required.
- [ ] `.github/workflows/docs.yml` builds with `mkdocs build --strict` on PRs and deploys to GitHub Pages from `main`, using current (non-Node-20) action versions.
- [ ] CLAUDE.md documents how to build and preview the docs.

## Risk Assessment

- Strict builds fail on broken links; hardware docs written before the site exists may need link fixes.
- GitHub Pages must be enabled for the repo with "GitHub Actions" as the source — a maintainer action.
- mkdocstrings needs the package importable; vendor SDKs must stay lazily imported or the API reference build breaks.

## Dependencies

- foundation_20261012 for `docs/guide.md`, `docs/hardware/README.md`, and the first public API. Can start any time after the Foundation's Phase 5; content grows with each driver track.

## Out of Scope

- Versioned docs (per release) — revisit when the package reaches PyPI.
- Read the Docs hosting.
