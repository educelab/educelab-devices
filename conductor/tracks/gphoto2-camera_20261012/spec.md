# Specification: gphoto2 Camera

**Track ID:** gphoto2-camera_20261012
**Type:** Feature
**Created:** 2026-10-12
**Status:** Draft

## Summary

Port the gphoto2 DSLR/mirrorless camera to a `FileCamera` driver (`educelab.devices.cameras.gphoto2`) with settings, live view, keep-alive, recovery, and a `FocusDrive`, verified on a Nikon Z7 II.

## Context

The current implementation is `GPhoto2Camera` in `pgs-scan` `spectral-processing-module` (`SpectralCapture.py:559-1049`), which returns saved file paths and takes app-specific arguments (`shutter_widget`, `on_log`, `cancel_event`). Focus drive code exists only on `usb-dslr-capture-demo` remote branches (`origin/ankan:capture-gui.py`, tested on a Sony a6300). ADR 0002 fixes the capture shape: camera files in memory, no decoding.

## User Story

As a developer of spectral imaging software, I want to capture the camera's native files into memory, adjust exposure in seconds, watch live view, and step focus so that I can save NEFs for posterity and process the same bytes without re-reading them.

## Acceptance Criteria

- [ ] `[gphoto2]` extra: `gphoto2; sys_platform != "win32"` and Pillow; lazy import; libgphoto2 logging bridged to Python `logging`.
- [ ] `GPhoto2Camera` is a `Device` and `FileCamera`; `discover()` uses camera autodetect (model, port).
- [ ] `open()` errors: USB claim (`-53`) raises `DeviceBusy` whose message names `ptpcamerad` and the documented workaround; an empty bus (`-105`) is retried a bounded number of times, then raises `DeviceNotFound`. The library never kills processes.
- [ ] `capture_files()` returns every file one shutter release produces (e.g. RAW + JPEG) as in-memory `CameraFile`s; downloads are retried a bounded number of times; a capture in flight blocks keep-alive and concurrent captures.
- [ ] Settings are `Setting` descriptors from the camera's config tree; canonical `exposure_time` (seconds) lists the discrete shutter speeds as `choices`, so consumers pick one with `Setting.nearest()`; other settings are reachable by native widget name.
- [ ] `preview_frame()` enables live view as needed (`viewfinder` / `eosviewfinder` / `d1a6`, continuous AF off) and returns an ndarray decoded with Pillow.
- [ ] Keep-alive runs on an internal daemon thread, paused during capture and stopped on `close()`.
- [ ] `cam.focus` is a `FocusDrive` when the camera exposes a range-type `manualfocusdrive` (Nikon, Sony), else `None`: `step(n)` chunks large moves, waits a settle time per chunk, retries busy (`-110`), and raises `FocusLimitReached` on the end-stop error; `drive_to_limit()` steps until the limit; the step counter resets at each limit.
- [ ] Tests run against an injected fake gphoto2 layer (no libgphoto2 needed); `Camera`/`FileCamera`/`FocusDrive` contract suites pass; tests skip on Windows where the extra can't install.
- [ ] `docs/hardware/gphoto2-cameras.md` with a Nikon Z7 II section (widgets, error codes, focus behavior, live-view quirks, `ptpcamerad`).
- [ ] `el-devices dslr` subcommand: detect, list settings, capture to a directory, focus step.

## Dependencies

- foundation_20261012 (Camera, FileCamera, FocusDrive ABCs; `CameraFile.save`; contract suites; CLI skeleton).

## Out of Scope

- Raw decoding (rawpy) — ADR 0002.
- Canon choice-type `manualfocusdrive` (`Near/Far 1–3`) — future feature, tested later against the lab's Canons.
- Focus range measurement (`measure_range`) and focus stacking.
- Streaming captures directly to disk (files fit in memory).
- Migrating the spectral prototype to this driver.

## Technical Notes

- `-113` as the end-stop error and `-110` as busy were observed on a Sony a6300; confirm the codes on the Z7 II before relying on them, and record what the Z7 II reports.
- Settle timing from `origin/ankan`: 100 ms + 0.5 ms/step, capped at 3 s; treat as a starting point to verify.
- Pause live view around focus limit seeking (the original code did this to avoid deadlocks) — the device lock may make this unnecessary; verify.
- Workflow recovery (reconnect between sequence steps, retry vs. abort) stays with consumers; the driver handles transient errors only.
