# Specification: Light Channel Concurrency

**Track ID:** light-concurrency_20261119
**Type:** Feature
**Created:** 2026-11-19
**Status:** Complete

## Summary

Every light declares whether its channels can be lit together (`INDEPENDENT`) or only one at a time (`EXCLUSIVE`), so consumers can set up captures knowing whether two channels can be on at once.

## Context

The MISHA panels light one band at a time: lighting a channel above zero turns the others off (`docs/hardware/misha.md`, "One band at a time"). The XLC2 drives its white strip and 940 nm array from separate outputs. Consumers such as `pgs-scan` can't tell these apart today without knowing the driver.

Design settled with the maintainer on 2026-11-19. Other states were considered and left out because no lab light has them: a limit on how many channels can be lit, several channels sharing one level, exclusivity within groups of channels, and a total power budget. MISHA stays exclusive for good. A planned variant that replaces two UV bands with IR1050 LEDs will drive several LED groups from one channel, so it stays exclusive too.

`CONTEXT.md` already defines **Exclusive light** and notes that **Channel** is preferred over "band".

## User Story

As a developer of a consumer such as `pgs-scan`, I want to know whether a light's channels can be lit at the same time, so that I can set up captures (and their UI) without knowing which driver is behind the light.

## Acceptance Criteria

**Role**
- [x] `ChannelConcurrency(StrEnum)` with `INDEPENDENT = "independent"` and `EXCLUSIVE = "exclusive"`, exported from `educelab.devices.lights`.
- [x] `Light.concurrency` is an abstract property, so every `Light` must declare one.
- [x] On an `EXCLUSIVE` light, setting a level above 0 makes the base `Light` record the other channels as 0 in its remembered levels. Setting a channel to 0 leaves the others' remembered levels alone.
- [x] Exclusive lights keep switching channels without raising. Nothing new raises.

**Drivers**
- [x] `MishaLight` is `EXCLUSIVE`.
- [x] `XLC2` and `Foldio360Halo` are `INDEPENDENT`.
- [x] `SimulatedLight(concurrency=...)` defaults to `INDEPENDENT`. When it's `EXCLUSIVE`, it turns the other channels off the way MISHA does.

**Contract**
- [x] `LightContract` checks behavior against the declared value:
  - `EXCLUSIVE`: lighting B after A leaves A at 0, and setting an unlit channel to 0 leaves the lit one on.
  - `INDEPENDENT`: A and B stay lit together.
  - Lights with one channel skip both checks.
- [x] Existing contract tests hold for exclusive lights. For example, `test_all_off` mustn't assume every channel was lit at once.
- [x] `SimulatedLight` runs the contract in both modes.

**Docs**
- [x] `docs/guide.md`: `concurrency` in the Light row of the role table, and a note under "Light levels".
- [x] `MishaLight` docstring and `docs/hardware/misha.md` name the `EXCLUSIVE` declaration.
- [x] `docs/hardware/xlc2.md` records the `INDEPENDENT` declaration and the hardware check that backs it.

**Hardware (batched, final phase)**
- [x] XLC2: light white and 940 nm together and check both stay on. Add this to `tests/test_xlc_hardware.py`, and record the result in `xlc2.md`.

## Dependencies

- Existing code: `lights/base.py`, `lights/misha.py`, `lights/xlc.py`, `lights/simulated.py`, `lights/__init__.py`, `stages/foldio360.py` (`Foldio360Halo`), `tests/contracts/lights.py`, the light test modules.
- No dependency on other tracks.

## Out of Scope

- Limited count, shared level, grouped exclusivity, and power-budget states.
- A `can_light_together()` helper.
- Raising when an exclusive light is asked to light a second channel.
- MISHA firmware changes, including the IR1050 variant.
- An ADR. The change is easy to reverse and not surprising.

## Technical Notes

- `MishaLight` reads its levels from the panel, so the base class's remembered-level bookkeeping matters mainly for `SimulatedLight` and future exclusive drivers that can't read their levels back.
- Adding an abstract property is a breaking change for any `Light` subclass outside this repo. Note it in the release notes.
