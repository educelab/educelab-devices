# Specification: Camera Preview Mode

**Track ID:** preview-mode_20261102
**Type:** Feature
**Created:** 2026-11-02
**Status:** Draft

## Summary

Make preview an explicit camera state with a requested preview region and output size, so consumers can frame shots and assist focus at native resolution without pulling full frames over the link. The design is recorded in [ADR 0007](../../../docs/adr/0007-preview-is-an-explicit-camera-state.md).

## Context

`preview_frame()` is stateless today. GenICam cameras grab a full-resolution frame and stride it down on the host, so a preview costs as much as a capture. gphoto2 switches live view on at the first preview and off at `close()`, and also switches continuous AF off. `pgs-scan` previews one camera at a time on its own timer, and stops and restarts preview around captures. Focus assist needs a zoomed region at native pixels, which neither backend offers through the API.

## User Story

As a lab developer building an acquisition app, I want to start a preview of a chosen sensor region at a bounded size and pull fresh frames from it, so that operators can frame shots and judge focus quickly on any camera.

## Acceptance Criteria

- [ ] `Camera` has `start_preview(region=None, max_size=None) -> PreviewGeometry`, `stop_preview()`, and a `preview` property (`None` when not previewing). Calling `start_preview()` while previewing reconfigures. `stop_preview()` is a no-op when idle, and `close()` ends preview.
- [ ] `preview_frame(not_before=None)` returns a `PreviewFrame` (pixels in the camera's current pixel format, timestamp, geometry) and raises outside preview. During preview, `capture_frame()` and `capture_files()` raise.
- [ ] The region is a box in sensor fractions (default: the full sensor). `max_size` caps the longest side (`None`: no reduction), and `min_size` is a floor: the most reduction that keeps at least that many pixels. `PreviewGeometry` reports the region (sensor fractions, after rounding) and the output `width`/`height` the camera actually applied.
- [ ] GenICam drivers use hardware ROI and decimation where discovery showed they work, and fall back to host crop and stride elsewhere. The canonical `width`/`height` settings keep reporting the capture size.
- [ ] gphoto2 keeps live view on only between `start_preview()` and `stop_preview()`, maps the region and size to `liveviewzoomarea`/`liveviewsize` (plus the zoom center if discovery shows one can be set), reports those native settings read-only, and no longer touches continuous AF.
- [ ] `not_before` waits for a later frame: by timestamp on GenICam, by arrival on gphoto2. A camera that can't time its frames refuses it.
- [ ] Settings can be changed during preview and apply to preview frames. Preview respects the trigger mode.
- [ ] The camera contract suite covers preview, and every driver and both simulated cameras pass it.
- [ ] `docs/guide.md` documents the preview state and the snapshot pattern (stop, capture, start). Each camera's hardware doc records the discovery results and its preview mechanism. `el-devices` subcommands that preview use the new API.

## Dependencies

- Existing code: `cameras/base.py`, the GenICam core (`_genicam.py`) and its three backends, `gphoto2.py`, `simulated.py`, `tests/contracts/cameras.py`.
- Hardware: the Nikon Z7 II, CM3-U3-50S5M and IDS U3-36P0XCP for discovery and the hardware checks.
- Approved: the `Preview` and `Preview region` glossary terms, and ADR 0007.

## Out of Scope

- Migrating `pgs-scan` to the new API.
- Designing for several cameras previewing at once on a shared link (it should work, but nothing is optimized for it).
- Preview-only exposure or other preview-specific settings.
- Raw control of live-view knobs outside the preview API (ADR 0007, Q25 option (c)).
- Push or streaming frame delivery (ADR 0001).
- Focus scoring or autofocus algorithms. These belong to consumers.

## Technical Notes

Hardware discovery comes first and sets which code path each model takes:

1. What `viewfinder=1` does to the Z7 II's rear screen and EVF.
2. Whether `changeafarea` moves the Z7 II's zoom center.
3. Whether a Z7 II preview requested after a focus step can still show the lens from before it.
4. Whether the CM3 and IDS can change ROI offsets (and size) while streaming.
5. Which binning and decimation modes each model has, and whether they average or sum.

Binning must average, or be compensated, so preview brightness matches capture. On the IDS, never set `TLParamsLocked` (`docs/hardware/ids-u3-36p0xcp.md`).
