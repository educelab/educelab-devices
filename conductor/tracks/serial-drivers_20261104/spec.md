# Specification: Lab Board Connection and GRBL Link

**Track ID:** serial-drivers_20261104
**Type:** Refactor
**Created:** 2026-11-04
**Status:** Pending

## Summary

Two serial deepenings. A **lab board** connection, in a new `_lab_board.py`, owns the ADR 0004 open sequence that MISHA and XLC2 each copy today. A GRBL link, in a new `stages/_grbl.py`, takes the protocol engine out of the X-Carve stage. The Stage base also gains a way to lose homing, which replaces X-Carve's override of `_homed`.

From the architecture review of 2026-11-04. "Lab board" is defined in `CONTEXT.md`.

## Problem Description

**Lab boards.**
- `_serial` offers shallow helpers: `handshake`, `command`, `parse_version`, `only_port`, `port_with_serial_number`.
- `MishaLight._open` (`lights/misha.py:144-173`) and `XLC2._open` (`lights/xlc.py:114-150`) repeat the same sequence almost line for line: find the port, build the transport, open it, handshake, check the minimum firmware, raise with reflash steps, and close on any failure.
- The constructors, `info`, `hardware_version`, `_require_transport` and `_default_transport` are copied too, and partly in `stages/xcarve.py`.
- The copies have drifted. XLC2 searches by serial number on open even when a transport was passed in, and so replaces it; MISHA and X-Carve don't. The reflash message is built two different ways.
- About 12 tests are mirrored between `test_misha.py` and `test_xlc.py`.

**GRBL.**
- About 300 of `stages/xcarve.py`'s 821 lines are a protocol engine: reply, orphan and reset accounting, the status sequence, alarm epochs, and the reader thread (203-230, 524-781). Nothing separates it from the stage logic.
- Race tests therefore patch privates: `write_line`, `_idle_status`, `_command`, `_home` and `_alarms` (`test_xcarve.py:636-646, 677, 719-731, 784`).
- The Stage base can't say "an alarm lost homing", because `home()` sets `_homed = True` after `_home()` returns. X-Carve gets around this by overriding `_homed` with a property under `type: ignore[override]` (`xcarve.py:349-357`).

## Acceptance Criteria

- [ ] `_lab_board.py` holds a lab board connection, configured per board with the ID command, identity parser, minimum firmware, reflash doc and port match. It owns finding the port, opening it, the handshake, the firmware check and closing after a failed open.
- [ ] MISHA and XLC2 each *hold* a lab board connection (composition) and keep only their channel behaviour. Roles stay single-inheritance.
- [ ] A transport passed in always wins and is never replaced. A serial number is looked up again on each open. Port and serial number are mutually exclusive. One reflash message format.
- [ ] A `LabBoardContract` runs against both firmware fakes and replaces the mirrored tests.
- [ ] X-Carve shares the port-resolution part only.
- [ ] `stages/_grbl.py` holds the GRBL link, tested directly against `fakes/grbl.GrblMachine`. Its rules hold: one reply per line, abandoned lines, and a reset discarding owed replies. No test patches X-Carve privates to provoke a race.
- [ ] The Stage base has `_homing_lost()`, which a driver may call from any thread. `home()` records a reference generation when it starts, and `is_homed` is true only while that generation is unchanged.
- [ ] X-Carve's epoch bookkeeping for homing and its `_homed` override are gone.
- [ ] `docs/guide.md` (homing) and the hardware docs reflect any change callers could notice.
