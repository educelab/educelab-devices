# Specification: Spinnaker Camera

**Track ID:** spinnaker-camera_20261012
**Type:** Feature
**Created:** 2026-10-12
**Status:** Draft

## Summary

Port the FLIR/Teledyne Spinnaker cameras from `pgs-scan` `dev` to a `SpinnakerSystem` (enumeration) and a per-camera `FrameCamera` driver, fixing the known buffer and stale-frame defects.

## Context

On `dev`, `SpinnakerCameraController(QObject)` (`pgs_scan/components/cameras.py`) and `CardinalDirectionRig` (`camera_rigs.py`) mix enumeration, rig-wide settings, broadcast capture, and stale-frame rejection, all over Qt signals. Known defects: the stale-frame loop leaks PySpin buffers and is unbounded (#83), the incomplete-image check is skipped on the returned frame, and `_remove_cameras` clears the list it iterates (#90). PySpin is not on PyPI, and as of Spinnaker SDK 4.4.0 it only ships cp310/cp312 wheels and requires numpy<2.

## User Story

As the `pgs-scan` developer, I want each Spinnaker camera behind the `FrameCamera` interface, with reliable frames no older than a requested time, so that my rig code only decides which cameras capture together.

## Acceptance Criteria

- [ ] PySpin imported lazily; a missing PySpin raises an `ImportError` pointing to `docs/hardware/spinnaker.md` install steps.
- [ ] `SpinnakerSystem` owns the PySpin `System` instance (shared, released when the last user closes), and `discover()` returns serial number and model per camera; enumeration/removal has no #90 bug.
- [ ] `SpinnakerCamera(serial)` is a `Device` and `FrameCamera`; open configures continuous acquisition with newest-only buffering.
- [ ] Settings: canonical `exposure_time` (seconds), `gain`, `pixel_format`, with auto modes; ranges reported via `Setting` descriptors.
- [ ] `capture_frame(not_before=ts, timeout=…)` rejects frames older than `ts` using a measured device-to-host timestamp offset, with bounded retries; **every** grabbed buffer is released (fixes #83); incomplete images are rejected on every frame; `Frame` metadata includes timestamp and retry count.
- [ ] `preview_frame()` returns the newest frame.
- [ ] Acquisition start/stop semantics are decided and documented (implicit on demand vs. explicit), recorded in the hardware doc. (Decided 2026-10-15: continuous from `open()` to `close()`, because it is fastest.)
- [ ] Tests run against a fake PySpin module; `Camera`/`FrameCamera` contract suites pass.
- [ ] `docs/hardware/spinnaker.md`: SDK install, Python 3.12 only, numpy<2 requirement, version coupling.
- [ ] `el-devices spinnaker` subcommand: list cameras, capture N frames, capture-latency benchmark (like `pgs-scan` `utils/system_check.py`).

## Dependencies

- foundation_20261012.

## Out of Scope

- Rig orchestration: broadcast capture, rig-wide settings, capture timeouts across cameras (consumer; e.g. `pgs-scan`'s `CardinalDirectionRig`).
- Per-camera config persistence (`QSettings`).
- A PyPI-installable PySpin.

## Technical Notes

- `not_before` replaces the rig's `request_ts`; the timestamp-latch offset (median of 20 samples) is measured on open and can be re-measured.
- CI cannot install PySpin; all CI coverage comes from the fake module. Hardware tests run on a Python 3.12 rig machine.
